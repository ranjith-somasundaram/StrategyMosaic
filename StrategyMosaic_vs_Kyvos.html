Semantic layer for AI & BI · Evaluation guide

Strategy Mosaic and Kyvos

Both vendors now describe themselves as a semantic layer for AI and BI. They start from different places. Kyvos is built around pre-computing aggregates so queries return fast at very large scale. Mosaic is a governed semantic layer inside a complete analytics and AI platform, running live against your sources or in-memory, model by model. For programmes that must run in their own environment with their own LLM, that difference shapes everything that follows.

Kyvos optimises analytical execution at scale. Strategy Mosaic provides a governed semantic foundation across BI and AI.

01At a glance
Kyvos · core design
Performance-first semantic layer
  • AI-driven "smart aggregation" recommends and builds aggregates from query history, then refreshes them incrementally as data changes.
  • Serves SQL, MDX and DAX to BI tools and Excel.
  • Kyvos reports sub-second analytics on billion-row workloads with thousands of users.
Kyvos · AI
AI Space, Dialogs, MCP
  • AI Space scopes context and tools per use case, and agents connect over MCP.
  • Dialogs is its analytics agent, available in Teams and Slack, with model routing.
  • Business Knowledge Graphs are announced as "coming soon".
Mosaic · core design
Governed semantic layer in a full platform
  • One certified model over 200+ data sources, served to Strategy BI, Power BI, Tableau, Excel, apps and agents.
  • Each model runs live, in-memory or both, and Sentinel recommends when to switch.
  • Dashboards, pixel-perfect reporting, mobile and embedding are part of the same platform.
Mosaic · control
Sovereign by design
  • Customer Managed Cloud runs the full platform on your own Kubernetes, on-prem or in your cloud account.
  • Bring your own LLM, including open-source and offline models.
  • Mosaic Sentinel covers audit, risk, usage, cost and query performance.

Where Kyvos is genuinely strong. Sub-second analytics over billions of rows at high concurrency is Kyvos's heritage, and it is a credible choice for migrating large legacy OLAP cubes (such as SSAS) to the cloud. If raw aggregate query speed on a very large existing data lake is the single deciding criterion, test it head-to-head.

03Setting the record straight

Kyvos publishes a "Kyvos vs Strategy" comparison. It describes Strategy as an in-memory BI tool, which does not reflect Mosaic. Here is each claim with the current facts.

Kyvos says

"Strategy is a widely used BI tool known for its in-memory aggregation capabilities."

Current Strategy capabilities

Strategy is a BI platform and the Mosaic Universal Semantic Layer. Mosaic models can run live against the source, in-memory, or both, and Sentinel recommends when to switch. In-memory is an option, not the architecture.

Kyvos says

Strategy data size is "Limited".

Current Strategy capabilities

In live mode, Mosaic queries your warehouse or lakehouse directly, so data size follows your data platform rather than Strategy's memory. In-memory is used where it helps.

Kyvos says

Strategy user concurrency is "Low", with "failover secondary servers" for HA.

Current Strategy capabilities

Concurrency is a sizing question, not a product label. Strategy runs as clustered services and supports highly available production environments. The fair answer is a concurrency test on your own workload.

Kyvos says

Strategy incremental refresh has a "1M row capacity" and "No" indexing.

Current Strategy capabilities

The comparison cites no product version, documentation or test. Ask Kyvos for the source, and Strategy will validate it against the release you would deploy. Live-mode models don't depend on refresh at all.

05Where the value comes from

The two platforms are designed to create value in different places. The question for each customer is which of these value pools is largest in their programme.

Level 1
Infrastructure value

Faster queries and lower warehouse compute, through pre-aggregation, caching and query acceleration. Largest where very large data volumes meet heavy, repetitive query load.

Kyvos's core design
Level 2
Platform value

Semantic layer, dashboards, reporting, mobile, embedded analytics and AI agents on one platform, with centralised security and audit, instead of several products to integrate and run.

Strategy's core design
Level 3
Enterprise value

Both define KPIs once and reuse them. The difference is reach: governed KPIs delivered through reports, mobile, embedded apps and AI agents on the same platform, with less duplicated logic and manual reporting.

Strategy's broader reach
Decision principleDon't pay for extreme-scale acceleration if the real challenge is KPI complexity, governance and enterprise-wide adoption. If acceleration is the challenge, test it on your largest workload.
06Two paths
Path A · Architecture option

Consolidated Strategy architecture

  • One platform for the semantic layer, dashboards, reporting, mobile and AI agents, with centralised security and audit.
  • Runs on Customer Managed Cloud in your own environment, with your own LLM.
  • Live for freshness, in-memory for speed, chosen model by model.
  • Sentinel shows usage, cost and performance from day one.
Path B · Architecture option

Strategy with an existing Kyvos layer

  • Kyvos lists Strategy as a supported BI tool and connects to it live.
  • Kyvos keeps accelerating very large aggregate workloads. Strategy BI delivers dashboards, reporting, mobile and AI to users.
  • A possible coexistence architecture: Mosaic governs the definitions that sit outside Kyvos, with the option to consolidate later.
