Section 1
Architecture recap
Strategy One + Mosaic (Universal Semantic Layer)
Overview

Strategy's platform has two pillars. Strategy One is the AI+BI platform — enterprise reporting, interactive dashboards, mobile, embedded analytics, and HyperIntelligence, all served through Library (end-user) and Workstation (admin/developer).

Strategy Mosaic is the Universal Semantic Layer (USL) underneath it — a single governed model that connects 200+ data sources and defines business logic, calculations, and security once, then reuses it everywhere: dashboards, AI agents, third-party BI tools, productivity apps (Teams, Excel, PowerPoint), and now external AI assistants via MCP.

Mosaic Studio is the AI-assisted modeling tool (up to 10x faster build), and Mosaic Sentinel provides governance intelligence across the model (Risk Management, Audit & Compliance, Usage Insights).

Section 2
AI Agents
Web, mobile, embedded, HyperCards, Teams, voice
Overview

Auto AI Agents (Auto 2.0) are conversational analytics bots grounded entirely in the governed Mosaic model. The same agent can be deployed across:

  • Web Library — full chat interface with visual answers and an interpretation trace
  • Mobile — native iOS/Android, including voice commands
  • Embedded — inside enterprise apps such as Salesforce
  • HyperCards — zero-code hover cards on any web app that expand into a full agent chat

Auto Voice now runs multiple actions in parallel (retrieve data, calculate, summarize) with lower latency and more natural turn-taking, powered by Gemini.

Section 3
Trust & accuracy
Governed answers, interpretation, feedback loop
Overview
1Grounded in governed data, not raw guessing
  • The agent queries the governed semantic model — never source systems directly
  • This is the core mechanism that eliminates hallucinations, since calculations and relationships are pre-defined, not invented at query time
2Transparent, traceable reasoning
  • The AI Interpretation feature shows exactly how the AI arrived at its answer — filters, aggregation, and grouping applied
  • Every interaction is traceable, so a business user can validate the logic without needing to read SQL
3(Additionally) Enterprise-grade governance via Mosaic Sentinel
  • Risk Management — real-time risk alerts and scoring for sensitive data access
  • Audit & Compliance — a complete audit trail of who accessed what data and when
  • Usage Insights — visibility into how the semantic layer is actually being used
Discussed in this session
  • Raised the core question of how a business user can trust an answer without reading SQL or citations, and whether there's a confidence score
  • Explained the 95%+ baseline accuracy comes from the agent only querying the governed semantic model, never external sources directly — and if requested data isn't available, it says so rather than guessing
  • Clarified the LLM only interprets the question (e.g. what "growth" or "last year" means); the query and all calculations are built by Strategy's own engine, which is what prevents hallucination
Section 4
Data architecture & connectivity
Caching, SAP HANA/BW, hosting model, governance
Overview
1Managed, multi-cloud deployment — with private/on-prem options
  • Strategy is hosted as a managed service on any major cloud — Azure, Google Cloud, or AWS — connecting out to on-prem or cloud sources via secure links (VPN tunnels, private links)
  • For organizations needing full operational control, Customer Managed Cloud (CMC) lets Strategy One be deployed within your own cloud account or your own private data center — built for regulated industries like banking, health, and government
  • Strategy AI also supports offline/local LLM models (e.g. open-source models like LLAMA or GPT-OSS/Gemma), so the AI layer itself can run without sending data to an external cloud AI provider
2Two data-access modes, chosen per use case
  • Cached — frequently-used data held in-memory on the Strategy server, avoiding per-query cloud consumption costs from the source system
  • Live/real-time — queried directly at the source when near-real-time freshness is needed, including blending across multiple sources in one view
3SAP connectivity — two distinct paths
  • API-based (OData) — the standard SAP BW, BW/4HANA, and S/4HANA connectors work over OData, an open, no-license-fee API layer; Strategy connects to a published service URL, never the database directly. Import-only, refreshed on a schedule rather than live. Source ↗
  • Direct database connection — Strategy also offers a direct SAP HANA connector via ODBC or JDBC, with SSO support, for environments where database-level access is permitted. Source ↗
  • These are two genuinely different access levels — worth confirming which one fits TAFE's environment before committing to either
4Governance layered on top — Mosaic Sentinel
  • Risk Management — real-time risk alerts and scoring for sensitive data access
  • Audit & Compliance — complete audit trail of who accessed what data and when
  • Usage Insights — visibility into how the semantic layer is actually being used
Discussed in this session
  • Explained the cache vs. live-query decision framework based on usage patterns (how many users, how often)
  • Confirmed the cache server cannot sit on TAFE's own AWS account — it's tied to Strategy's managed deployment
  • Discussed SAP HANA connectivity in detail, including BW-for-HANA, which was confirmed as a usable route

Section 8
MCP & open ecosystem
Claude, Gemini, Copilot connecting to Mosaic
Overview
1MCP support — AI freedom
  • Strategy supports the Model Context Protocol (MCP)
  • Users can interact with Strategy AI Agents from any MCP-compatible platform — ChatGPT, Claude, Copilot Studio, Gemini, Amazon Quick Suite
  • Same governed data, calculations, and security as inside Strategy One, regardless of which AI interface a team prefers
2Where the LLM is actually used
  • Building the semantic model — dimension/fact/join discovery
  • Powering individual agents — custom instructions per agent
  • Driving Auto Narrative
  • Each stage uses the LLM differently — not one generic pass
3Semantic layer build speed
  • No pre-built industry accelerators exist today for platforms like SAP or PLM systems
  • AI compresses the manual modeling effort instead — 1–2 weeks down to roughly an hour
  • AI recommends joins, relationships, and relevant KPIs for a human to validate — not a fully automated build
Discussed in this session
  • Demoed a third-party AI tool querying the Mosaic model directly over MCP, blended with an external data source in the same conversation
  • Clarified where the LLM is used across the platform — model building, agents, and narratives each use it differently
  • Confirmed no pre-built SAP/PLM accelerators exist yet; AI-assisted modeling is the current alternative

Section 10
Security & compliance
Certifications, access control, AI data privacy, governance
Overview
1Independent certifications and audits
  • ISO 27001 Certified and SOC 2 Type II audited (Managed Cloud Enterprise)
  • FedRAMP-authorized cloud offering (MicroStrategy Cloud for Government)
  • PCI DSS compliant cloud platform, HIPAA-compliant cloud solution, SOX-compliant corporate financial systems, BSI C5 (Germany) assessed
2Multi-layered data access control (built into the platform itself)
  • Security Filters — row-level, dynamic filtering based on the logged-in user's attributes; e.g. a regional manager automatically sees only their region's data, from the exact same report every other user runs
  • Access Control Lists (ACLs) — object-level permissions (read/write/execute/control) on every report, dashboard, and data object, inheritable down to child objects
  • Privileges — action-level control over what a user can do (run a report, create an object, use a specific tool) — separate from what data they can see
  • Security Roles — bundled privilege sets that stay reusable and consistent across multiple projects/departments
  • Database connection mapping by group — different user groups can be automatically routed to different underlying databases for the same report
3Authentication
  • Supports OIDC, SAML, SSO, LDAP/Active Directory, Kerberos, and standard username/password
  • LDAP/AD group mappings can drive Strategy group membership automatically, so access stays in sync with the identity provider rather than being manually maintained
4Data protection in transit and at rest
  • HTTPS/TLS for data in transit
  • AES-256 encryption for data at rest
5AI data privacy — two different architectures, two different guarantees
  • With CMC + a self-hosted/offline LLM: data doesn't need to leave TAFE's own environment at all — the model runs inside your infrastructure, so there's no external transmission to begin with
  • With a cloud-hosted LLM (e.g. Gemini via BYOE) or a third-party AI interface via MCP: the relevant prompt/data context is sent to that provider's endpoint to generate a response — but Strategy's configuration is set to prevent that provider from retaining or training on it
6Mosaic-specific protections
  • LLM Shielding — protects sensitive data from being inappropriately exposed to the LLM layer itself, on top of the row/object-level controls already covering the underlying data
  • Object-level and row-level security carry through automatically into every AI agent built on Mosaic — an agent can't surface data a user wouldn't otherwise be entitled to see, regardless of how the question is phrased
7Mosaic Sentinel — governance intelligence
  • Risk Management — real-time risk alerts and intelligent risk scoring for sensitive data access
  • Audit & Compliance — complete audit trail of who accessed what data and when, supporting regulatory frameworks like GDPR, HIPAA, and SOX
  • Usage Insights — visibility into how the semantic layer is actually being used, so governance isn't guesswork
